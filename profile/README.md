# 🚶 [서비스명]

> **산책의 순간과 감정을 놓치지 않도록, AI가 기록을 도와주는 감성 산책 기록 서비스**

## 📌 서비스 소개

`[서비스명]`은 일상 속 산책을 자동으로 감지하고, 사용자가 남긴 사진·감정·동반자·상황 등의 정보를 바탕으로 AI가 산책 기록 작성을 도와주는 서비스입니다.

사용자가 직접 긴 글을 작성하지 않아도 간단한 경험 정보만 남기면 AI가 산책 일기의 제목과 본문을 생성하며, 사용자는 결과를 확인·수정한 뒤 자신의 산책 경험으로 저장할 수 있습니다.

### 핵심 흐름

```text
산책 감지
   ↓
기록 제안
   ↓
사진·감정·동반자·상황 기록
   ↓
AI 산책 일기 생성
   ↓
사용자 확인·수정
   ↓
산책 경험 저장
   ↓
아카이브 및 감정·동반자 필터
```

---

## ✨ 핵심 기능

* 🚶 산책 활동 감지 및 기록 제안
* 📝 감정·동반자·상황 중심의 간단한 경험 기록
* 📷 산책 사진 기록 및 최근 사진 선택
* 🤖 AI 기반 산책 일기 제목·본문 생성
* ✏️ AI 생성 결과 확인 및 수정
* 🗂️ 산책 경험 아카이브
* 🔍 감정·동반자 기반 간단 필터

## 🌿 Branch Convention

```text
main
├── develop
│   ├── feature/{기능명}
│   ├── fix/{수정내용}
│   └── refactor/{리팩토링내용}
```

### Branch

* `main`: 최종 배포 가능한 코드
* `develop`: 개발 통합 브랜치
* `feature/*`: 새로운 기능 개발
* `fix/*`: 버그 수정
* `refactor/*`: 기능 변경 없는 코드 개선

예시:

```text
feature/walk-candidate
feature/experience-draft
feature/walk-archive
fix/ai-generation-error
```

## 💬 Commit Convention

| Type       | 설명         |
| ---------- | ---------- |
| `feat`     | 새로운 기능 추가  |
| `fix`      | 버그 수정      |
| `refactor` | 코드 리팩토링    |
| `style`    | 코드 스타일 변경  |
| `docs`     | 문서 수정      |
| `test`     | 테스트 코드     |
| `chore`    | 설정 및 기타 작업 |

### 예시

```text
feat: 산책 후보 생성 API 구현
fix: AI 생성 실패 상태 처리
refactor: 산책 경험 조회 로직 개선
docs: README API 설명 추가
chore: 프로젝트 초기 설정
```

## 🔀 Pull Request 규칙

* 기능 개발은 별도 Branch에서 진행합니다.
* 작업 완료 후 `develop` 브랜치를 대상으로 PR을 생성합니다.
* PR 생성 전 로컬에서 정상 동작 여부를 확인합니다.
* 가능하면 본인이 작성한 코드를 한 번 검토한 후 PR을 생성합니다.
* 다른 팀원의 작업 영역을 수정한 경우 PR 설명에 반드시 작성합니다.
* Merge 전 충돌 여부를 확인합니다.

### PR 제목 예시

```text
[FEAT] 산책 후보 생성 API 구현
[FIX] 산책 기록 조회 오류 수정
[REFACTOR] Experience 서비스 로직 정리
```

---

## 🤝 협업 규칙

* 새로운 작업 시작 전 담당 기능과 Branch를 확인합니다.
* `main`, `develop` 브랜치에 직접 작업하지 않습니다.
* 다른 팀원의 작업 파일을 수정해야 하는 경우 먼저 공유합니다.
* API Request/Response 또는 DB 구조 변경 시 프론트엔드·백엔드 담당자에게 공유합니다.
* API 명세서와 데이터 테이블을 기준으로 구현합니다.
* 구현 중 명세 변경이 필요한 경우 코드만 임의로 변경하지 않고 팀과 먼저 공유합니다.
* `.env`, API Key, 비밀번호 등 민감한 정보는 Git에 업로드하지 않습니다.

## 🎯 MVP 개발 원칙

* 24~48시간 내 구현 가능한 핵심 기능을 우선합니다.
* MVP 범위를 벗어나는 기능은 구현보다 안정적인 핵심 흐름 완성을 우선합니다.
* 복잡한 확장 기능보다 다음 핵심 사용자 흐름의 완성을 우선합니다.

```text
산책 감지 → 경험 입력 → AI 생성 → 최종 저장 → 아카이브 조회
```
