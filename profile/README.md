# 🚶 MOWA | 모와

### Moment & Walk, 걸으며 순간을 모으다.

> **산책의 시작과 끝을 놓쳐도, 그 순간의 감정과 기억은 놓치지 않도록.**
> 걷기 활동을 자연스럽게 포착하고 AI와 함께 하나의 산책 경험으로 기록하는 감성 산책 아카이빙 서비스입니다.

---

## 📌 About MOWA

산책은 항상 "지금부터 산책해야지"라고 생각하며 시작되지 않습니다.

밥을 먹고 집으로 돌아가는 길, 친구와 이야기하며 걷는 시간, 생각을 정리하기 위해 나선 길처럼 일상의 흐름 속에서 자연스럽게 시작되고 끝나는 경우가 많습니다.

**MOWA**는 사용자가 직접 산책의 시작과 종료를 기록하지 않아도 걷기 활동을 감지해 기록할 순간을 제안합니다.

사용자는 사진과 감정·동반자·상황 등 최소한의 정보만 남기면 되고, AI가 흩어진 단서를 하나의 산책 일기로 구성합니다.
생성된 기록은 사용자가 직접 확인하고 수정한 뒤 자신의 산책 경험으로 저장할 수 있습니다.

---

## 💡 Why MOWA?

기존의 걷기 서비스가 주로 **거리·시간·걸음 수와 같은 운동 데이터**를 기록한다면, MOWA는 산책에서 실제로 기억에 남는 **사람·감정·장소·상황의 맥락**에 집중합니다.

### MOWA가 중요하게 생각하는 네 가지 가치

* 🚶 **자연스러운 포착**
  사용자가 산책 시작·종료를 직접 선언하지 않아도 걷기 활동을 기반으로 기록할 순간을 제안합니다.

* 👆 **최소한의 개입**
  걷는 동안에는 경험 자체에 집중하고, 기록은 사진과 몇 번의 선택만으로 끝낼 수 있도록 합니다.

* 🤖 **경험의 맥락화**
  시간·장소·사진·감정·동반자 등의 단서를 AI가 하나의 산책 경험으로 연결합니다.

* 📚 **회상 가능한 보존**
  단순 활동 기록이 아닌, 시간이 지난 뒤에도 당시 상황을 떠올릴 수 있는 경험으로 저장합니다.

## 🔄 Core Flow

```text
걷기 활동 감지
      ↓
산책 기록 후보 생성
      ↓
걷기 종료 후 기록 제안
      ↓
사진 · 감정 · 동반자 · 상황 입력
      ↓
AI 산책 일기 생성
      ↓
사용자 확인 · 수정
      ↓
산책 경험 최종 저장
      ↓
아카이브 · 캘린더 · 태그 기반 조회
```

## ✨ Key Features

### 🚶 1. 산책 활동 감지 및 기록 제안

스마트폰의 활동 정보를 활용해 걷기 활동을 감지하고, 걷기가 종료된 시점에 산책 기록을 제안합니다.

모든 걷기를 자동으로 산책으로 확정하지 않고 사용자가 `남기기 / 건너뛰기`를 선택할 수 있습니다.

### 💭 2. 최소 경험 기록

긴 글을 작성하지 않아도 다음과 같은 최소한의 정보만 선택해 산책 경험을 남길 수 있습니다.

* 사진
* 감정
* 동반자
* 상황

### 📷 3. 산책 사진 기록

산책 중 직접 촬영한 사진이나 최근 사진을 대표 이미지로 선택할 수 있으며, 사진 없이도 기록을 계속할 수 있습니다.

### 🤖 4. AI 산책 일기 생성

산책 시간·장소와 사용자가 입력한 경험 정보를 기반으로 AI가 산책 일기의 **제목과 본문**을 생성합니다.

AI는 사용자가 제공하지 않은 대화·감정·사건을 새롭게 만들어내지 않고, **실제로 존재하는 경험의 단서를 하나의 맥락으로 연결하는 역할**을 합니다.

### ✏️ 5. AI 결과 확인 및 수정

AI가 생성한 결과를 바로 저장하지 않습니다.

사용자가 제목·본문·사진·감정·태그 등을 직접 확인하고 수정한 뒤 최종 산책 경험으로 확정합니다.

### 🗂️ 6. 감성 산책 아카이브

완성된 산책을 단순 활동 데이터가 아닌 하나의 **산책 경험**으로 보관합니다.

* 대표 사진
* 산책 일기
* 날짜 및 시간
* 장소
* 감정
* 동반자
* 상황
* 태그

### 📅 7. 캘린더 · 태그 기반 조회

저장된 산책 경험을 날짜별로 확인하거나 최종 태그를 기준으로 다시 찾아볼 수 있습니다.

## 🧩 Experience Lifecycle

MOWA의 산책 기록은 세 단계의 데이터 흐름으로 관리됩니다.

```text
WalkCandidate
산책 기록 후보
      ↓
ExperienceDraft
사용자 입력 + AI 생성 결과
      ↓
WalkExperience
사용자가 최종 확정한 산책 경험
```

AI 결과는 사용자의 확인 전까지 최종 경험으로 저장되지 않으며, 최종 `WalkExperience`는 이후 조회 시 독립적으로 사용할 수 있도록 Snapshot 형태로 보존됩니다.

## 🛠 Development Convention

<details>
<summary><b>🌿 Branch Convention</b></summary>

```text
main
├── develop
│   ├── feature/{기능명}
│   ├── fix/{수정내용}
│   └── refactor/{리팩토링내용}
```

* `main` : 최종 배포 가능한 코드
* `develop` : 개발 통합 브랜치
* `feature/*` : 새로운 기능 개발
* `fix/*` : 버그 수정
* `refactor/*` : 기능 변경 없는 코드 개선

예시:

```text
feature/walk-candidate
feature/experience-draft
feature/walk-archive
fix/ai-generation-error
```

</details>

<details>
<summary><b>💬 Commit Convention</b></summary>

| Type       | Description |
| ---------- | ----------- |
| `feat`     | 새로운 기능 추가   |
| `fix`      | 버그 수정       |
| `refactor` | 코드 리팩토링     |
| `style`    | 코드 스타일 변경   |
| `docs`     | 문서 수정       |
| `test`     | 테스트 코드      |
| `chore`    | 설정 및 기타 작업  |

예시:

```text
feat: 산책 후보 생성 API 구현
fix: AI 생성 실패 상태 처리
refactor: 산책 경험 조회 로직 개선
docs: README 서비스 소개 수정
chore: 프로젝트 설정 변경
```

</details>

<details>
<summary><b>🔀 Pull Request & Collaboration</b></summary>

* 기능 개발은 별도 Branch에서 진행합니다.
* `main`, `develop` 브랜치에서 직접 작업하지 않습니다.
* 작업 완료 후 PR을 통해 코드를 병합합니다.
* PR 생성 전 로컬 환경에서 정상 동작 여부를 확인합니다.
* 다른 팀원의 작업 영역을 수정한 경우 PR에 변경 내용을 명시합니다.
* API Request/Response 또는 DB 구조 변경 시 프론트엔드·백엔드 담당자에게 공유합니다.
* API 명세서와 데이터 테이블을 기준으로 구현합니다.
* 명세 변경이 필요한 경우 코드만 임의로 수정하지 않고 팀과 먼저 공유합니다.
* `.env`, API Key, 비밀번호 등 민감한 정보는 Git에 포함하지 않습니다.

</details>
